## 1. 背景

### 1.1 需求来源

《押韵ground truth.docx》给出了 7 组上古韵文（《天问》《九章·惜诵/涉江/橘颂》《卜居》《招魂》《大招》）的押韵标注。这些作品普遍存在**句末语气词**（之、兮、乎、些、只），真正的韵脚是**语气词前一个实字**：

| 示例 | 句末语气词 | 真韵脚（ground truth） |
|---|---|---|
| 《天问》 | 之 | 道/考、极/识、为/化、度/作 |
| 《惜诵》 | 兮 | 保/道 |
| 《涉江》 | 兮 | 远/坛、薄/薄、当/行 |
| 《橘颂》 | 兮 | 服/国、志/喜、摶/烂、道/醜、异/喜、求/流、过/地、友/理、长/像 |
| 《卜居》 | 乎 | 忠/穷、耕/名/身/生/真/人/清/楹、驹/凫/躯、轭/迹、翼/食 |
| 《招魂》 | 些 | 方/祥、托/索/石/释、止/齿/祀/醢/里 |
| 《大招》 | 只 | 昭/遽/逃/遥、流/悠/胶 |

### 1.2 与既有决策的关系

- 上古韵技术方案 v0.3（`docs/上古韵检测功能技术方案.md`）§1.3 非目标：**语气词自动识别原定「本期不做，由用户自行调整」**，并注明「后续可考虑通过**句末重复出现规则**优化识别效果」；
- 本方案将该条目从「不做」升级为「**启发式自动判定**」，口径仍保持宽口径、不引入语言学精细建模。

### 1.3 现状问题（已复现）

现有 `free_rhyme` 的韵脚候选 = 句末 / 标点前 / 空格前的 CJK 字（见 §3.1）。上古韵 + 楚辞体时，语气词被当作韵脚候选并自组成韵组，真韵脚完全丢失：

```
输入《天问》2 联     →  韵组 [之, 之]（之职）        ✗ 应为 道/考（幽觉）
输入《涉江》2 联     →  韵组 [兮, 兮]（歌）          ✗ 应为 远/坛（元乾）
输入《招魂》2 句     →  韵组 [些, 些]（支锡）        ✗ 应为 托/索/石/释（鱼铎）
```

### 1.4 数据侧已初验与开发中发现的数据问题

ground truth 全部韵对经 简繁归一 后均命中上古韵数据且同部（极/识→之职、道/考→幽觉、远/坛→元乾、服/国→之职、耕/名/生/清/楹→耕 且 身/真/人→真、忠/穷→冬、驹/凫/躯→侯屋、托/索/石/释→鱼铎、昭/逃→宵药、流/悠/胶→幽觉…）。仅两处 ground truth 注明「通押/合韵」需单独讨论（耕真通押、鱼宵合韵，见 Q6）。

**开发中发现的数据问题（已修复，见 `上古韵检测功能技术方案.md` v0.4 §3.3）**：
char_dict 中存在**繁简双键**（如 託/托），繁体键（託）仅有 平水韵/词林正韵，缺 上古韵 数据，导致《招魂》「託些」顺移后查无韵部。修复方式为**只把上古韵数据镜像到繁体键、不合并不删除**（后/後 等繁简字在平水韵下本是不同词条，合并会改变既有校验行为——已通过 shiva 380 项回归验证）。

## 2. 目标与非目标

### 2.1 目标

1. 上古韵（`book == Shangguyun`）下，自动识别**句末语气词**并将其排除出韵脚候选；
2. 排除后，韵脚候选**顺移**到语气词前的实字，再按现有规则分组；
3. 结果可观测：响应保留 `particles` / `shifted_from` 字段供调试与自动化测试断言；**前端静默处理**（评审确认，不在界面展示语气词判定结果）；
4. 其余韵书（平水韵/词林正韵/中华通韵）与上古韵非句末场景行为**完全不变**。

### 2.2 非目标（本期）

- 不做语言学级虚词性判定（不区分 代词/助词/叹词 等词性）；
- 不做跨韵部通押放宽（耕真、鱼宵 等，见 Q6）；
- 不改变 `validate_meter` 的 Shi/Ci 韵脚判定（见 Q2）；
- 语气词判定规则不开放给用户配置（仅内置常量，见 Q7）。

## 3. 现有自由诗韵脚检测规则（参考基线）

`fangcun-checker/app.py :: free_rhyme`（现行）：

1. **候选收集**：逐行取 CJK 字，若满足「标点前 / 空格前 / 句末」之一 → 候选（含 `line, pos, char, categories`）；
2. **分组**：贪心聚类——任取未分配候选作锚，向后找「韵部集合有交集」的候选归入同组；`merge_tones` 时归一 `_平/_仄` 后缀；
3. 响应：`{candidates, groups}`；前端 FreeEditor 按组着色、RhymePanel 取最大组推断韵部名。

本方案只在上古韵分支上，于步骤 1 之后、步骤 2 之前插入**语气词检测与顺移**。

## 4. 判定算法（两层启发式）

### 4.0 作用域

仅当 `rhyme_book_name == 'Shangguyun'` 时启用；新增请求参数 `strip_particles`（默认 `true`，可显式关闭）。其他韵书走原逻辑。

### 4.1 第一层：已知语气词表

分层词表（常量，置于 `app.py` 或独立 `config`）：

| 层 | 词表 | 处理 |
|---|---|---|
| **A 绝对语气词** | 兮、乎、也、矣、焉、哉、只、些、猗、旃 | 出现在候选位（句末/标点前）**直接排除**并顺移 |
| **B 条件性虚词** | 之、者、而、其、于、以、与(欤)、耶、邪、耳、已、云 | **仅当命中 4.2 重复规则**时才排除（否则保留，防误伤真韵字） |

分层理由（关键设计点）：

- 《关雎》「左右流之，寤寐求之」——**之 是真韵字**（之职部通押），若把 之 无条件下掉会误判；
- 《天问》「誰傳道之 / 何由考之」——**之 是语气词**，其重复出现（每联句末）可被 4.2 规则识别；
- 兮/乎/些/只 等几乎不作韵脚（楚辞通例），可安全直排；「魂兮歸來！」中 兮 位于句中+叹号前，也由本层覆盖（候选位命中）。

### 4.2 第二层：句末重复出现规则（会议原案）

- 统计**候选位**的字频；某字 出现次数 ≥ **2 次** → 判定为语气词（固定阈值，B 层专用）；
- **仅作用于 B 层词表字**（虚词）——**实词/未知字不因重复被排除**：ground truth《涉江》「死林薄兮 / 芳不得薄兮」中 薄/薄 为**同字押韵**（实词韵脚重复），若对任意字生效会误判；
- **不用占比阈值**（原 `max(2, ⌈候选位×30%⌉)`）：用户常以**空格分词**输入《诗经》，空格使每个分词都成为候选（如《野有死麇》13 个候选），30% 占比被稀释为 4，导致 之×2 不达阈值而漏判——规则已限 B 层虚词，固定 2 次安全且稳定；
- 词表外新语气词的自动发现（方言衬字等）本期不做，词表按需扩充（Q8）。

### 4.3 韵脚顺移（shift）

对每个被排除的语气词候选位：

1. 从该位置向前（`pos-1, pos-2, …`），跳过标点/空格/非 CJK；
2. 取最近一个 CJK 字作为新候选（`shifted_from` 记录来源）；
3. 若连续多个语气词（如「…也兮」）→ 继续回退直到非语气词实字；
4. 若回退到行首仍无实字 → 丢弃该候选。

### 4.4 回退保护（防全诗误判）

- 判定口径：**排除并顺移后若没有任何候选**（如全文仅「兮。兮。」）→ 回退保留语气词为候选，不吞掉整首诗的韵信息；
- 《惜诵》式**全部句末都是语气词（也）但顺移有产出**（保/道）→ **不回退**，正常执行（这是楚辞体的常规形态，不是误判）。

### 4.5 伪代码

```
def detect_and_shift(candidates, lines, strip_particles):
    if not strip_particles or book != 'Shangguyun':
        return candidates, []
    freq = Counter(c.char for c in candidates)
    threshold = max(2, ceil(len(candidates) * 0.3))
    excluded = {c for c in candidates
                if c.char in TIER_A
                or (c.char in TIER_B and freq[c.char] >= threshold)}
    if not excluded:
        return candidates, []
    particles, new_candidates = [], []
    for c in candidates:
        if c not in excluded:
            new_candidates.append(c); continue
        target = shift_back(c)            # 4.3（跳过标点/A 层词/已排除位）
        particles.append({...})
        if target is None: continue       # 丢弃
        if target already in new_candidates: continue
        new_candidates.append(shifted(target))
    if not new_candidates:                # 4.4：顺移后仍无任何候选 → 回退
        return candidates, []
    return new_candidates, particles
```

## 5. 接口与前端变更

### 5.1 `POST /api/free_rhyme` 响应扩展（仅 Shangguyun）

```jsonc
{
  "candidates": [
    { "line": 0, "pos": 5, "char": "道", "categories": ["幽觉"], "shifted_from": { "line": 0, "pos": 6 } },
    { "line": 1, "pos": 5, "char": "考", "categories": ["幽觉"], "shifted_from": { "line": 1, "pos": 6 } }
  ],
  "groups": [ { "positions": [ { "line": 0, "pos": 5 }, { "line": 1, "pos": 5 } ] } ],
  "particles": [
    { "char": "之", "line": 0, "pos": 6, "reason": "repeat", "shifted_to": { "line": 0, "pos": 5 } },
    { "char": "之", "line": 1, "pos": 6, "reason": "repeat", "shifted_to": { "line": 1, "pos": 5 } }

}
```

### 5.2 前端（shiva）—— 本期无 UI 改动

## 7. Ground truth 固化为自动化测试（重点）

将 docx 7 个示例转为集成测试（`fangcun-checker`）：

1. **输入**：各示例原文按行（保留语气词与标点）；
2. **期望断言**：
   - 韵组中韵脚字集合/顺序与 docx 标注一致（如 天问 → 道/考 同组，之 不在组内；涉江 → 远/坛 同组）；
   - `particles` 内容正确（字、reason）；
   - 语气词排除后真韵脚**同部**（先做同组断言；韵部名断言按需）；
3. **数据回归防线**：断言每个 ground-truth 韵对在 Shangguyun 下同部（已初验全部成立；耕/真、鱼/宵 两个通押特例作为「已知例外」单独记录，见 Q6）；
4. 简繁归一：测试输入用原文繁体，断言命中简体数据（复用 `_lookup_char_dict` 的 t2s 回退）。

## 9. 评审结论

### 已确认（评审反馈）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 判定规则 | **两层都启用**：A 层词表兜底（兮乎些只等直排），B 层词表 + 重复规则处理 之/者/而/其/于 等可作韵字的虚词（§4.1） |
| Q2 | 作用域 | **v1 仅 free_rhyme**；validate_meter 接入另议（§4.0） |
| Q3 | 回退保护口径 | **仅「排除后无任何剩余候选」才回退**（§4.4） |
| Q5 | 前端展示 | **静默处理**：前端不做任何展示/埋点，`particles`/`shifted_from` 仅作服务端调试与测试字段（§5） |
| Q6 | 跨部通押（耕真/鱼宵） | **本期不做**，另立「上古韵宽口径通押边界」方案 |

### 按默认值实现

| # | 项 | 默认 |
|---|---|---|
| Q4 | 重复阈值 | **固定 2 次**（B 层专用）；不用占比阈值——空格分词会稀释候选数导致漏判（《野有死麇》回归修复） |
| Q7 | `strip_particles` 参数 | 提供，默认 `true`；前端不暴露开关 |
| Q8 | A 层词表 | 兮、乎、也、矣、焉、哉、只、些、猗、旃（后续可扩充） |
