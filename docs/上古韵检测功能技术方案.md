## 1. 背景与目标

### 1.1 背景

方寸（南洋吟游·诗词创作画布）现有平水韵、词林正韵、中华通韵三部韵书，覆盖近体诗、词、自由诗场景。2026-08-20 会议确定新增**上古韵文检测**能力：面向《诗经》体、楚辞体、古风等上古韵文创作，提供押韵检测、韵部浏览、单字查询。

上古韵与中古韵的本质差异：

- 上古韵**无统一官方韵书**约束，押韵模式灵活，**跨声调通押（平上去入）**普遍；
- 判定口径采用**宽口径**（李志儒确认），避免规则过窄限制创作，同时展示**细分韵部**信息供用户自主判断；
- 数据体系采用**六元音细分体系**（120+ 细分韵部），按文献通押惯例**归并**为**王力韵部体系** 23 个标准韵部。

### 1.2 目标

1. **新增「上古韵」韵书**：**全体裁画板（诗 / 词 / 自由诗）均可选择**，技术上不做体裁限制（评审已确认）；
2. **宽口径押韵判定**：同一标准韵部内平、上、去、入、次入声默认可通押；押韵结果按**标准韵部名称**标记（如「鱼铎」「支锡」）；
3. **韵部浏览**：23 个标准韵部按固定顺序展示，部内字按**總出現次數倒序**排列，逐字展示**细分韵部 + 拟音标注**；
4. **单字查询**：字 → 上古韵部（标准韵部 + 细分韵部）+ 拟音 + 声调 + 释义（复用现有释义逻辑）；
5. **全系统简体化**：数据进入系统前**统一转为简体**，多繁→一简条目合并（评审已确认）。

### 1.3 非目标（暂不落地，会议明确排除）

| 项 | 说明 |
|---|---|
| 按地域 / 时间（前、后期上古）拆分韵部规则 | 高阶用户自行判断 |
| 用户手动调整押韵结果 | 优先保障自动判定准确率 |
| ~~语气词自动识别~~ | **已落地**：上古韵下句末语气词启发式判定（A 层词表直排 + B 层重复规则），见[独立方案](上古韵句末语气词启发式判定技术方案.md) |
| 文字学注释、典故类展示 | 不展示 |
| 上古 / 中古释义模块分离 | 直接复用现有释义 |
| 拟音采用中古音、普通话推导结果 | 只展示 ASCII 拟音（拼音列） |
| 无法正常显示的扩展平面字 | 直接剔除，不入库 |

## 2. 总体设计

### 2.1 架构定位

```
前端 (shiva / write.sjtuguoxue.space)
  └─ RhymePanel / FreeEditor / Dictionary
       │  /api/rhyme/list · /api/rhyme/lookup · /api/char/lookup · /api/validate_meter · /api/free_rhyme
       ▼
格律检测服务 (fangcun-checker / checker.sjtuguoxue.space)   ← 上古韵数据唯一事实来源
       ├─ static/config/char_dict.json     (字 → 韵部，含 Shangguyun)
       └─ static/config/rhyme_books.json   (韵部 → 字，新增 Shangguyun)
```

- 上古韵数据进入系统后**全为简体字**；用户输入的繁体字沿用现有 `t2s_map.json`（繁→简）回退即可命中，无需新增简→繁映射（评审已确认）；
- 押韵判定链路：Shi/Ci 画板走 `validate_meter`（平仄按上古声调注记，押韵按标准韵部），Free 画板走 `free_rhyme`（同标准韵部即同组）；
- 韵部浏览 / 单字查询走 `rhyme/list`、`rhyme/lookup`、`char/lookup`；
- `shiva/static/config` 与 Android 离线包内的数据文件需同步（数据镜像，见 §7）。

### 2.2 术语表（全部简体化）

| 术语 | 含义 | 数据来源（Excel 列） |
|---|---|---|
| 标准韵部（押韵判断韵部） | 归并后的 23 个韵部（如 鱼铎、支锡、脂质至、元乾），押韵判定唯一依据，**押韵按此名称标记** | `押韵判断采用韵部` |
| 细分韵部 | 六元音体系 120+ 韵部（如 鱼平、铎入），供展示与用户判断 | `韵` + `調` |
| 王力韵部 | 学术细分（32 值，如 鱼、铎），标准韵部的归并前成分，供展示 | `“王力韵部”` |
| 拟音（ASCII） | 上古音标注，避开 IPA 特殊字符显示问题 | `拼音`、`韵拼音`（拟音第 2、3 列） |
| 出现频次 | 部内字排序依据（**總出現次數**，非整数非空记号视为 1） | `總出現次數` |
| 声调 | 平 / 上 / 去 / 入 / 次入；**平仄注记：平=平，上/去/入/次入=仄** | `調` |

## 3. 数据模型与构建

### 3.1 数据源概览（PBOCYinjie8.20.xlsx）

| Sheet | 行数 | 用途 |
|---|---|---|
| `ZidianBiao` | 11,290 行（10,005 个不同字） | **主表**：逐字音韵信息，本方案唯一输入 |
| `XiaoyunBiao` | 4,016 | 小韵聚合表（校验/交叉验证用，不直接入库） |
| `QieyunXiaoyunBiao` | 3,386 | 切韵小韵表（广韵系，与本功能无关，v1 不处理） |
| `Yun` | 62 | 六元音细分体系网格（韵尾×元音→细分韵部名），确认细分体系结构用 |
| `YunPailie` | 23 | **标准韵部固定顺序表**（鱼铎、支锡、侯屋、之职、脂质至、幽觉、宵药、阳、耕、东、蒸、冬、歌、微、月祭、物队、元乾、文、真、叶、缉、谈、侵） |

关键数据事实（已核验）：

- `押韵判断采用韵部` 共 **23 个值**，与 `YunPailie` 完全一致（简体化后：鱼铎、支锡、侯屋、之职、脂质至、幽觉、宵药、阳、耕、东、蒸、冬、歌、微、月祭、物队、元乾、文、真、叶、缉、谈、侵）；
- `“王力韵部”` 共 32 个值，9 组阴入配对 + 14 个单部归并为 23 个标准韵部，例如：鱼+铎→鱼铎（871+290=1161 ✓）、脂+质至→脂质至（264+268=532 ✓）、元+乾→元乾（996+144=1140 ✓）；
- `調` 含 5 类：平 4644 / 上 2208 / 入 2100 / 去 1800 / **次入 524**（次入声按文献通押惯例并入 月祭/物队/脂质至，r 乾并入 元乾，无需额外规则）；
- 14 行 `押韵判断采用韵部` 为 None（如 𪏘、歶 等无音韵地位的生僻字）→ **剔除**；
- 10,005 字中 **1,083 字存在多行**（多音/多调，如 子 上去、王 平去）→ 一个字可对应多个细分韵部/多调，需按“读音”建模；
- 非 BMP 扩展平面字 411 个（𤟤、𪊨…）→ **剔除**（前端字体无法正常显示，会议明确）；CJK 扩展 A 区 444 个（䪡、䱇…）→ 可正常显示，**保留**；
- 源表繁简混排（為 ✓ / 为 ✗，與 ✓ / 与 ✗，無 ✓ / 无 ✓）→ **构建期统一转简 + 多繁→一简合并条目**（见 §3.3）；
- `總出現次數`：整数 8,450 行 / `√` 2,211 行 / 空 629 行 → 排序键：整数原值、`√` 记 1、空记 0。

### 3.2 派生数据结构

#### 3.2.1 `char_dict.json`（fangcun-checker/static/config）——每字新增 `rhymes.Shangguyun` 与 `shangguyun` 元数据

保持 `rhymes.Shangguyun` 为**韵部名字符串数组**（兼容现有 `_get_char_rhymes` / `_check_same_category` / `free_rhyme` / `char/lookup` 全部既有逻辑），同时新增平行的 `shangguyun` 字段承载展示元数据（多读音用数组）。**所有键与值为简体**：

```jsonc
// char_dict.json 新增字段示例（字：夫，源表为「夫」，简体不变）
"夫": {
  "tones": ["平"],
  "rhymes": {
    "Pingshuiyun": ["七虞"],
    "Cilinzhengyun": ["第3部_平"],
    "Zhonghua_Tongyun": ["五姑_平"],
    "Shangguyun": ["鱼铎"]              // ← 新增：标准韵部（去重后）
  },
  "shangguyun": [                        // ← 新增：展示元数据，一个元素 = 一个读音
    {
      "sub": "鱼平",                    // 细分韵部（韵列 + 調，简体）
      "wangli": "鱼",                   // 王力韵部（简体）
      "cat": "鱼铎",                    // 标准韵部（该读音所属押韵判断韵部）
      "py": "pa",                       // 拟音：拼音列（全音节）
      "rpy": "a",                       // 韵拼音列（韵母部分）
      "tone": "平",                     // 調：平/上/去/入/次入
      "freq": 5277                      // 總出現次數（排序键；√→1，空→0）
    }
  ]
}

// 繁→简合并示例（为 ← 為；如「為」与「为」两行同字，合并为一个条目）
"为": {
  "rhymes": { "Shangguyun": ["歌", "鱼铎"] },   // 多个繁体形体的标准韵部取并集
  "shangguyun": [
    { "sub": "歌平", "wangli": "歌", "py": "waj", "rpy": "aj", "tone": "平", "freq": 300 },
    { "sub": "鱼平", "wangli": "鱼", "py": "wa", "rpy": "a", "tone": "平", "freq": 120 }
  ]
}

// 多读音示例（字：子，上声/去声两行，同属之职 → 韵部去重为一个）
"子": {
  "rhymes": { "Shangguyun": ["之职"] },
  "shangguyun": [
    { "sub": "之上", "wangli": "之", "py": "tsyq", "rpy": "yq", "tone": "上", "freq": 11934 },
    { "sub": "之去", "wangli": "之", "py": "tsyh", "rpy": "yh", "tone": "去", "freq": 11934 }
  ]
}
```

> 设计说明：
> 1. 不把元数据塞进 `rhymes.Shangguyun` 的字符串里（避免破坏现有 checker 的 `Set[str]` 语义与序列化契约），用独立字段按需读取；
> 2. 已有条目（如 `无`、`后`）**保留原有 tones / 其他韵书 rhymes 不动**，仅追加 `Shangguyun` 相关字段；简化为新字（char_dict 中不存在）时创建条目，`tones` 取 調 映射（平→平，上/去/入/次入→仄），`rhymes` 仅含 `Shangguyun`；
> 3. 同一简体字来自多个繁体形体时：`shangguyun` 数组直接拼接（各自读音），`rhymes.Shangguyun` 取并集去重。

#### 3.2.2 `rhyme_books.json`——新增 `Shangguyun` 韵书（全部简体）

```jsonc
"Shangguyun": {
  "name": "Shangguyun",
  "categories": {
    "鱼铎": {
      "name": "鱼铎",
      "tone_type": "Z",              // ← 不新增枚举；该值仅占位，平仄推导不依赖它（见 §4/§5）
      "characters": ["之", "以", "不", "其", "曰", "子", "人", "有", "大", "无", "…"],
                                     // ↑ 按 總出現次數 倒序（§3.4）
      "relations": {},               // 上古韵无邻韵概念
      "subcategories": {             // ← 新增：细分韵部 → 字（展示/统计用，简体）
        "鱼平": ["夫", "玞", "砆", "…"],
        "鱼上": ["斧", "甫", "父", "…"],
        "鱼去": ["赋", "傅", "…"],
        "铎入": ["各", "落", "…"]
      }
    }
    // … 共 23 个标准韵部，key 顺序即 YunPailie 固定顺序
  }
}
```

### 3.3 构建脚本（`build_shangguyun_db.py`，置于 fangcun-checker 仓库）

流程：

1. **读取** `PBOCYinjie8.20.xlsx` 的 `ZidianBiao`（openpyxl，`data_only=True`）；
2. **过滤**：
   - 剔除 `押韵判断采用韵部` 为 None 的行（14 行，含 歶 等无音韵地位字）；
   - 剔除非 BMP 扩展平面字（411 个，`ord(ch) > 0xFFFF`）；
3. **统一转简**：全部字段（字、标准韵部、细分韵部、王力韵部）经 OpenCC（`prebuild.py` 已依赖）t2s 转简体；`押韵判断采用韵部` 23 个值转简后必须与简体 `YunPailie` 顺序表一一对应，否则报错；
4. **按简体字分组合并**：
   - 同一字多行（多音/多调）→ `shangguyun` 读音数组；
   - 多繁→一简（如 為→为、與→与、關→关、無→无）→ 条目合并：读音数组拼接、`rhymes.Shangguyun` 并集去重；
   - 已有 char_dict 条目追加字段，新字创建条目（`tones` 按 §3.2.1 注 2）；
5. **排序**：部内 `characters` 按 排序键（§3.4）倒序；`subcategories` 内同样排序；
6. **繁键镜像**：char_dict 中存在的**繁体键**（如 託，仅有 平水韵/词林正韵）补齐 `rhymes.Shangguyun` 与 `shangguyun` 读音（从简体键复制）——**只镜像上古韵数据，不合并不删除**（后/後 等繁简字在平水韵下本是不同词条，合并会改变既有校验行为；用保留「乾」的简化函数映射，避免 元乾 被误处理）；
7. **产出**：更新 `char_dict.json`（增量合并，不覆盖其他韵书字段）与 `rhyme_books.json`（追加 `Shangguyun`）；
8. **镜像**：同步写入 `shiva/static/config/`（Android 离线包与主服务静态数据，§7）；
9. **统计与自检**：输出各韵部字数、总字数、合并/剔除数量，并对齐简体 `YunPailie` 23 部顺序（顺序不一致即报错）。

> 运行时无需新增繁简映射：用户输入繁体走 checker 现有 `t2s_map.json` 繁→简回退（`_lookup_char_dict` / `_t2s` 已实现），数据全简后自然命中。

### 3.4 部内字排序键（替代现有现代汉语字频逻辑）

评审确认：**按 `總出現次數` 倒序**；非整数非空记号（`√`）视为 **1**，空值视为 **0**。

```
排序键：freq = 總出現次數（int 原值；'√'→1；空→0）
主序：freq 倒序
末位：按字（Unicode）稳定排序
```

> 例（鱼铎部内）：之(19118) → 以(14354) → 不(14121) → 其(12686) → 曰(12100) → 子(11934) → 人(11381) → 有(10893) → 大(7088) → 无(6386) → …

## 4. 押韵判定逻辑（宽口径）

### 4.1 判定规则

- **同部通押**：两个押韵字同属一个标准韵部（`押韵判断采用韵部`，如 鱼铎）即判定押韵成立。平、上、去、入、次入同部**默认可通押**（数据层面已归并，无需运行期规则）；
- **押韵标记**：押韵结果按**标准韵部名称**标记（如「鱼铎」「支锡」），不按平仄标记；
- **平仄注记**（用于 Shi/Ci 画板的格律检测）：按上古声调注记 **平=平，上/去/入/次入=仄**；多读音平仄不一致时按「中」（A）处理；
- **特殊分类**：次入声（月祭/物队/脂质至 内含 s 韵尾字）、r（乾，并入 元乾）已按文献通押惯例归并进标准韵部，**零代码处理**；
- **无邻韵/通韵概念**：上古韵 `relations` 为空，不引入额外宽容；
- **句末语气词**：free_rhyme 上古韵下自动排除（A 层词表直排 + B 层重复规则，韵脚顺移至语气词前实字），详见[上古韵句末语气词启发式判定技术方案](上古韵句末语气词启发式判定技术方案.md)。

### 4.2 运行链路

- **Shi / Ci 画板**（`validate_meter`）：
  - 押韵：`_check_same_category` 直接兼容（字 → 标准韵部集合 → 交集非空即通过）；
  - 平仄：`_get_char_tones(char, 'Shangguyun')` 需新增分支——从 `shangguyun` 元数据取 `tone`（平→P，上/去/入/次入→Z），多读音平仄不一致返回 `{'A'}`（中）；**不再从韵部 `tone_type` 推导**（部内跨调，单值无意义）；
- **Free 画板**（`free_rhyme`）：候选字取 `rhymes.Shangguyun`（标准韵部），同组即同韵。参考自由诗在中华通韵下的平仄混押实现（`merge_tones` 归一化 `_平/_仄` 后缀）：上古韵韵部名无 `_平/_仄` 后缀、**已在数据层完成合并**，混押天然成立，`merge_tones=true` 为无操作、不受影响。

## 8. 测试计划

### 8.1 数据层（构建脚本自检 + 单测）

- 23 个标准韵部与简体 `YunPailie` 顺序完全一致；
- 部内字数为简体去重后数量（如 鱼铎=939、元乾=898、支锡=475；与源表行数 1161/1140/583 的差异来自繁简合并、多读音去重与生僻字剔除）；
- 剔除数量正确（无韵部 14 行 + 非 BMP 741 行；最终入库 9,006 个简体字）；
- 繁简合并：為/为、與/与、關/关 合并为同一简体条目，读音数组正确拼接；無/无 命中同一条目；
- 排序键样例断言（之 19118 > 以 14354 > 不 14121 > 其 12686）；`√` 记为 1（如 砆）、空记为 0。

### 8.2 判定逻辑

| 用例 | 期望 |
|---|---|
| 鱼平 + 鱼上 + 铎入 通押（如 夫/斧/各） | 同组，无错误 |
| 次入声通押（月祭 内 at/et/ot + as/es/os） | 同组 |
| 元乾 通押（乾 r 韵尾 + 元 n 韵尾同部） | 同组 |
| 出韵（鱼铎 vs 歌） | 不同组 |
| 平仄注记：夫→平(P)、斧→仄(Z)、上/去/入/次入→仄 | `_get_char_tones` 正确 |
| 多读音平仄不一致（如 子 上去混读） | 返回 中(A) |
| `merge_tones=true` 时不受影响 | 分组结果不变 |
| Shi 画板 + 上古韵（五绝/七律）| validate_meter 正常返回，平仄/押韵均按上古规则 |

### 8.3 接口层

- `rhyme/list?book=Shangguyun` 顺序正确，`tone_type` 为 `"Z"`；
- `rhyme/lookup` 返回 `details` 且与 `characters` 对齐；其他韵书响应无 `details`（不回归）；
- `char/lookup`、`char/batch` Shangguyun 扩展字段正确；`free_rhyme` 分组正确；
- 繁体输入（为/与/关）经 t2s 回退可命中简体条目。

### 8.4 前端

- 新建画板（诗/词/自由诗）→ 切换上古韵 → 输入《诗经》韵例（如「关关雎鸠，在河之洲」鸠/洲 同部）→ 同组标色；

## 10. 评审结论与开放问题

### 已确认（评审 v1 反馈）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 部内字排序主键 | **按 `總出現次數` 倒序**；`√` 等非整数非空记号视为 1，空视为 0（§3.4） |
| Q2 | 「上古韵」韵书开放范围 | **全量开放**：诗 / 词 / 自由诗画板均可选，技术上不做额外判断（§6.1） |
| 繁简 | 字形与条目合并 | **全系统统一简体**；多繁→一简合并条目（读音拼接、韵部并集）（§3.3） |
| tone_type | 韵部平仄标记 | **不新增枚举**；声调注记按 平=平，上/去/入/次入=仄（逐字从 `調` 推导）；押韵按标准韵部名称标记（如「鱼铎」），参考中华通韵自由诗平仄混押实现（§4/§5） |
| Q5 | 拟音标注展示粒度 | **全音节 `拼音`**（如 `paq`）；`韵拼音` 随数据入库备用（§6.1 双行标注 `细分韵部 · 拼音`） |
| Q6 | 数据基线固化 | **按默认处理**：`PBOCYinjie8.20.xlsx` 为 v1 基线，构建脚本记录源文件 sha256（f5563555…e8c），可重复执行、数据源后续更新走同一脚本 |
